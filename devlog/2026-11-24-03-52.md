# 2026-11-24 03:52 — 修复 run.bat：沙箱失败自动降级

## 现象

双击 `run.bat` 后 Electron 启动失败：

```text
[ELIFECYCLE] Command failed with exit code -2147483645.
[flowharness] startup failed.
```

`-2147483645` = `0x80000003`（STATUS_BREAKPOINT），与本项目 Phase 0/2 记录的环境限制一致：
受限终端/CI 无法初始化 Chromium 的 OS 沙箱，浏览器进程在 `ready` 之前就退出。

## 修复

`run.bat` 增加启动模式：

| 调用 | 行为 |
| --- | --- |
| `run.bat` | 先标准沙箱；失败后自动 `--no-sandbox` 重试一次 |
| `run.bat --no-sandbox` | 直接兼容模式 |
| `run.bat --sandbox` | 强制标准模式，失败不重试 |
| 环境含 `ELECTRON_RUN_AS_NODE=1` | 直接兼容模式（宿主本身是 Electron 时必定受限） |

重试时会明确打印原因，最终失败则提示两种启动方式并 `pause`。

## 验证

在受限会话中不带参数运行（`FLOWHARNESS_SMOKE=1`）：

```text
[flowharness] mode: auto
[ELIFECYCLE] Command failed with exit code -2147483645.
[flowharness] standard launch failed; retrying with --no-sandbox ...
[flowharness] restricted terminals / CI cannot initialize Chromium's sandbox.
[main] renderer-ready {"phase":"run","data":{"runId":"run_551c...","status":"completed","error":null}}
```

随后进程以 **exit code 0** 正常退出，说明重试链路与正常结束判定都正确。

## 说明

普通桌面终端首次启动应直接成功，不会触发重试；只有确实无法初始化沙箱的环境才会走兼容模式。
