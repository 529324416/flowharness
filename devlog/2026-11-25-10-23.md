# 开发日志 — 2026-11-25（多选崩溃修复）

> 本会话只保留这一篇。只记录实际交付，不记录过程、排错和实现细节。

## 问题复现

- 用 16 个节点执行 60 轮随机框选 / Ctrl 点选后，renderer 触发 React `Maximum update depth exceeded`（Minified React error #185）；
- 崩溃后 React Flow 节点全部卸载，页面不可用；
- 普通 2 节点框选、粘贴、问题面板定位不受影响。

## 根因

选中状态存在双向回灌：

```text
React Flow 选中变化
  → onSelectionChange → 父组件 selectedNodeIds
  → CanvasView effect setNodes(selected flags)
  → React Flow 再次发出选中变化
```

上一轮的去重只能挡住“相同集合”的重复事件；随机多选时 React Flow 与父层的选中集合/更新时序不断交错，仍会形成更新深度循环。

## 修复

- **选中状态改为 React Flow 本地主控**：
  - 框选 / 点选只通过 `onSelectionChange` 上报父层；
  - 删除“父层 selectedNodeIds → setNodes”的常驻 effect，不再回灌；
- **程序化选中改为一次性请求**：
  - CanvasView 新增 `selectionRequest: { nodeIds, seq }`；
  - 问题面板定位、粘贴后选中通过递增 seq 的请求应用一次；
- 文档投影仍使用 `selectedIdsRef` 保留当前选中；文档切换时清空选中请求。

## 验证

- 随机多选压力：16 节点 / 60 轮框选 + Ctrl 点选，最终 `nodes=16`、`selected=12`，无 React 异常；
- 普通框选：2/2 节点选中；
- 粘贴 / 撤销 / 重做：节点数 2 → 4 → 2 → 4；
- 问题面板：1 条问题，定位正常；
- FH：33 个测试文件 / 155 项测试通过；`pnpm typecheck` / `build` / `smoke` 通过。
