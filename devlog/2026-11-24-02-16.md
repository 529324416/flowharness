# 2026-11-24 02:16 — Phase 0：contracts + React renderer + 主题

## 目标

落实架构 Phase 0：建立跨进程契约包，把 renderer 从原生 TS 迁到 React，并接入 design tokens 与主题系统。

## 交付内容

### `packages/contracts`（L0）

- `ids.ts`：Workspace/Graph/Workbench/Run/Session/ContentHash 标识类型；
- `errors.ts`：`FhErrorCode`、`FhErrorDto`、`IpcResult<T>`、`ipcOk/ipcFail`；
- `domain.ts`：`ThemeMode`、`AppConfig`、`WorkspaceSummary`、`RunStatus`、`BlobMeta` 等 DTO；
- `ipc.ts`：全部 invoke 通道常量、send 通道、事件 topic、`IPC_EVENT_CHANNEL`、已实现通道的类型表；
- 以 **TS 源码**形式被消费（`exports` 指向 `src/index.ts`），由 electron-vite/Vite 负责编译；
- 不依赖 React / Electron / Node。

### React renderer

- `main.tsx`：`createRoot` 前用 `prefers-color-scheme` 写 `data-theme`，避免首帧闪白；
- `App.tsx`：Phase 0 自检界面（运行时版本 / Wireclaw / Graph 构造 / 状态栏）；
- `theme/ThemeProvider.tsx`：light/dark 切换，写入 `data-theme` 并调用 `window.flowharness.setTheme` 同步原生主题；
- `styles/tokens.css` + `styles/global.css`：语义化 design tokens（明/暗两套），组件不写死颜色；
- `bridge.d.ts`：`window.flowharness` 的类型（基于 contracts）。

### IPC

- preload 暴露 `setTheme` / `reportReady` 等白名单能力；
- main 新增 `theme:set` handler：校验参数 → `nativeTheme.themeSource` → 返回 `IpcResult`；
- 所有跨进程数据用 contracts 类型，不传类实例。

### 构建

- `@vitejs/plugin-react` 接入 renderer；
- `externalizeDepsPlugin` 排除 `wireclaw` 与 `@flowharness/contracts`（后者是 TS 源码，必须打包）；
- `pnpm-workspace.yaml` 增加 `packages/*`；根 `typecheck` 先跑 contracts 再跑 desktop。

## 遇到的问题

1. **`@vitejs/plugin-react` 的额外 peer**：`oxc-transform-react`、`@rolldown/plugin-babel`、`babel-plugin-react-compiler` 全部是 `optional`，当前只装插件本体与 React 即可，Vite 8/rolldown 下构建正常。
2. **`capturePage` 在受限会话中挂起**：隐藏窗口不产帧，`showInactive` 后仍超时；改为 `executeJavaScript` 读取 DOM 与 `getComputedStyle` 断言，绕开截图依赖。
3. **contracts 必须打包而非外部化**：它的 `exports` 指向 `.ts` 源码，若被 externalize，运行期 `require("@flowharness/contracts")` 会失败。已在 main/preload 的 exclude 列表里处理。
4. renderer 产物 626 kB（React + wireclaw 浏览器构建），Phase 3 接入画布后再评估代码分割。
