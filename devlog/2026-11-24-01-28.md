## 最终决策

| 决策 | 结论 |
| --- | --- |
| UI 框架 | **React 19** + Vite 8 + electron-vite 6；`tsc` 类型检查 |
| 画布 | **无框架 core + 薄 React 视图**；`@xyflow/react` 只作为 view 层实现细节 |
| 执行位置 | **main 进程**（RuntimeHost），未来可迁 utility process |
| 存储 | **目录 + manifest**，Blob 内容寻址，导出 `.fhws` |
| 布局 | `GraphDocument.ui` 可移植布局 + 工作台实例覆盖 |
| 工作台 | Framework / Instance / GraphDocument 三段式；多图优先用 subgraph |

## 为什么是 React（而不是 Vue）

用户此前有 Electron + Vue 经验，但本项目 UI 由 AI 实现，经验不是约束。真正的决定性因素有两条：

1. **画布生态**：react-flow 最成熟；
2. **工具链实证**：`vue-tsc@3.3.14` 与 `typescript@7.0.2` 不兼容——它 `require.resolve("typescript/lib/tsc")`，TS 7（原生版）不再导出该路径，实测直接崩溃。改用 `typescript@6.0.3` 后 vue-tsc 可正常工作（已验证），但需要在 desktop 里维护第二个 TS 版本。

React + 纯 `tsc` 在本仓库是零额外成本，因此定稿 React。

## 写作时核对过的 wireclaw 事实

- `IFileHost` 以 `contentHash` 为键（`read/readMeta/write/list/delete/flush/close`），去重/索引/GC 在 `AttachmentFileManager`；
- `Graph.run(options): GraphRun`、`Graph.resume(checkpoint, options)`，`GraphRun.pause(): Promise<GraphCheckpoint>`；
- `GraphEvent` 含 `run:start/node:*/custom/run:paused/run:resumed/run:end`；
- `EdgeDocument` 只有 `from`/`to` 端口地址、没有独立 id → 画布边 id 由端口推导；
- `GraphDocument.ui` 明确用于设计器坐标、运行时忽略 → 布局归属决策的依据；
- `createEditorCatalog(registry, { presets })` 提供节点目录与预设，设计器不应硬编码节点列表。

## 被否决的方案

- **Vue 3 + Vue Flow**：生态可用，但双 TS 版本与 vue-tsc 兼容风险；
- **renderer 内执行**：密钥/文件暴露，安全不可接受；
- **按 session 存附件**：破坏内容去重，与 `IFileHost` 语义冲突；
- **全部布局放实例文档或全部放 graph**：前者导出丢布局，后者无法多实例不同摆放；
- **单文件 JSON / 一开始上 SQLite**：前者损坏风险与写放大，后者调试与导入导出成本。
