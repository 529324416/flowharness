## 交付内容

### contracts

- 新增 `RunSnapshot`、`RunEventDto`、`RunEventBatch`、`RunStartRequest` 等 run 契约；
- 新增审批 / 用户输入 payload（`ApprovalRequestPayload`、`UserInputRequestPayload` 等）与 `*:respond` 通道；
- `RunStatus` 增加 `interrupted`；
- run 事件是 wireclaw `GraphEvent` 的**传输投影**（错误降级为消息，值走 `unknown`）。

### main / services

| 模块 | 要点 |
| --- | --- |
| `RuntimeHost` | 反序列化 GraphDocument → `graph.run()`；`start/pause/resume/cancel/get/list`；事件投影 + 16ms 批量；run 结束落库 |
| `RunStore` | `runs/<runId>/{meta,graph,events.jsonl,checkpoint}`；串行追加；写失败告警一次并内存降级；`markInterrupted()` |
| `SessionService` | 每个工作区一个 `AttachmentFileManager`，经 `WorkspaceFileHost` 落到 BlobStore |
| `RequestBroker` | requestId 等待器：审批超时默认 `deny`，用户输入超时默认 `cancelled` |

### IPC / 平台

- `run:start/pause/resume/cancel/get/list`；
- 事件统一走 `fh:event`（`topic: "run"` 批量推送）；
- `approval:respond`、`input:respond` 落回 broker；
- 打开工作区时自动 `markInterrupted()`，关闭时清理 Session / RunStore 缓存。

### renderer

- 新增「运行自检」卡片：一键启动 `Constant → Output` 的最小 Graph，消费事件流并展示状态/事件数/输出；
- `FLOWHARNESS_SMOKE=1` 时自动启动该 run，并在结束后上报 `phase: "run"`；
- smoke 现在同时校验：wireclaw 加载、数据层往返、自检 run `status: completed`。

## 设计取舍

1. **事件投影而不是直传**：IPC 只暴露稳定字段，`node:error` 降级为 `message`，避免 wireclaw 内部类型穿透。
2. **16ms 批量**：生命周期事件不丢弃、不重排；`node:stream` 天然合批，降低 IPC 频率。
3. **pause 才写 checkpoint**：wireclaw 只在暂停时产出 checkpoint；恢复仍需要原 Graph 定义，因此 run 目录同时保存 `graph.json`。
4. **自检 run 允许无工作区**：`workspaceId` 可选，无工作区时 store/attachments 缺省，便于 smoke 与 CI；正式工作台 run 必须带工作区。
5. **审批超时默认拒绝**：安全优先；UI 在 Phase 4 工作台里补齐。

## 已知限制

- `resolveProvider` 仍返回 `undefined`，模型/Agent 节点无法运行（等 Provider 工厂）；
- 审批/用户输入只有 IPC 管道，没有 UI；
- 跨进程重启的 resume 尚未接入（checkpoint 已落盘，缺工作台绑定与装载流程）；
- 受限环境写盘不可用：RunStore 内存降级，执行不受影响；单测在真实临时目录覆盖持久化路径。
